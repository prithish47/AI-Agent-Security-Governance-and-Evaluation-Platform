# AgentGuard — Development Guide

## Prerequisites

- Python 3.12+
- Node.js 20+ (LTS)
- Docker & Docker Compose
- Git
- PostgreSQL client tools (optional, for direct DB access)

---

## Quick Start

### 1. Clone and configure

```bash
git clone <repository-url>
cd Agent_Guard

# Copy environment template
cp .env.example .env

# Edit .env with your settings (defaults work for local dev)
```

### 2. Start with Docker Compose

```bash
# Build and start all services
docker compose up --build

# Or in detached mode
docker compose up --build -d
```

This starts:
- **PostgreSQL** on port 5432
- **Backend (FastAPI)** on port 8000
- **Frontend (Next.js)** on port 3000

### 3. Run database migrations

```bash
# In a new terminal, run migrations inside the backend container
docker compose exec backend alembic upgrade head
```

### 4. Verify

- Backend health: http://localhost:8000/health
- API docs: http://localhost:8000/docs
- Frontend: http://localhost:3000

## Local Development (Without Docker)

### Backend

```bash
cd backend

# Create virtual environment
python -m venv venv
venv\Scripts\activate  # Windows
# source venv/bin/activate  # Linux/Mac

# Install dependencies
pip install -r requirements.txt

# Set environment variables (or use .env file)
set DATABASE_URL=postgresql+asyncpg://agentguard:agentguard@localhost:5432/agentguard
set SECRET_KEY=dev-secret-key-change-in-production

# Run migrations
alembic upgrade head

# Start the development server
uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

### Frontend

```bash
cd frontend

# Install dependencies
npm install

# Set environment variables
# Create .env.local with:
# NEXT_PUBLIC_API_URL=http://localhost:8000

# Start development server
npm run dev
```

### Database

If not using Docker for PostgreSQL:

```bash
# Install PostgreSQL 17
# Create database
createdb agentguard
createuser -P agentguard  # Set password
```

## Key Development Workflows

### Adding a New API Endpoint

1. **Define the Pydantic schema** in the domain's `schemas.py`
2. **Implement the service function** in the domain's `service.py`
3. **Create the route handler** in `api/v1/endpoints/`
4. **Register the route** in `api/v1/router.py`
5. **Add tests** in `tests/`

### Adding a New Database Model

1. **Define the SQLAlchemy model** in `persistence/models.py`
2. **Generate a migration**: `alembic revision --autogenerate -m "Add new table"`
3. **Review the generated migration** (never blindly apply autogenerated migrations)
4. **Apply**: `alembic upgrade head`

### Adding a New Policy Rule

1. **Implement the rule** as a pure Python function in `policies/engine.py`
2. **Add it to the evaluation chain** in the correct order
3. **Write unit tests** that test the rule independently
4. **Write integration tests** that test it within the full evaluation chain

### Adding a New Tool

1. **Register the tool metadata** via the API (name, description, schema, risk level)
2. **Implement the executor function** in `tools/executors.py`
3. **Register it in the whitelist** in `tools/catalog.py`
4. **Write tests** for the executor

## Testing

### Running Tests

```bash
cd backend

# Run all tests
pytest

# Run with verbose output
pytest -v

# Run specific test file
pytest tests/test_policy_engine.py

# Run specific test
pytest tests/test_policy_engine.py::test_deny_rule_blocks_dangerous_tool

# Run with coverage
pytest --cov=app --cov-report=term-missing
```

### Test Categories

- **Unit tests** (`tests/unit/`): Test pure logic without database or network
- **Integration tests** (`tests/integration/`): Test with real database
- **Security tests** (`tests/security/`): Verify security boundaries

### Database Tests

Integration tests use a real PostgreSQL database. Set `TEST_DATABASE_URL` environment variable or the tests will use a test-specific database alongside your dev database.

## Environment Variables

| Variable | Description | Default |
|---|---|---|
| `DATABASE_URL` | PostgreSQL connection string | `postgresql+asyncpg://agentguard:agentguard@localhost:5432/agentguard` |
| `SECRET_KEY` | JWT signing secret | (required, no default) |
| `ACCESS_TOKEN_EXPIRE_MINUTES` | JWT access token lifetime | `30` |
| `REFRESH_TOKEN_EXPIRE_DAYS` | Refresh token lifetime | `7` |
| `GLOBAL_ITERATION_CEILING` | Max agent execution iterations | `20` |
| `OPENAI_API_KEY` | OpenAI API key | (optional) |
| `OPENAI_BASE_URL` | OpenAI-compatible API base URL | `https://api.openai.com/v1` |
| `GEMINI_API_KEY` | Google Gemini API key | (optional) |
| `OLLAMA_BASE_URL` | Ollama server URL | `http://localhost:11434` |
| `CORS_ORIGINS` | Allowed CORS origins | `["http://localhost:3000"]` |

## Debugging Tips

### Backend

1. **FastAPI auto-reload**: The dev server (`--reload`) restarts on file changes
2. **Swagger UI**: Interactive API testing at `http://localhost:8000/docs`
3. **SQL logging**: Set `SQLALCHEMY_ECHO=true` to see SQL queries
4. **Pydantic errors**: Validation errors show exactly which field failed and why
5. **Python debugger**: Add `import pdb; pdb.set_trace()` for interactive debugging

### Frontend

1. **React DevTools**: Install the browser extension
2. **Network tab**: Monitor API calls in browser dev tools
3. **Console errors**: Check browser console for TypeScript/runtime errors
4. **Next.js error overlay**: Shows compilation and runtime errors inline

### Database

```bash
# Connect to PostgreSQL directly
docker compose exec db psql -U agentguard -d agentguard

# Useful queries:
# List all tables
\dt

# Describe a table
\d agents

# Check recent audit events
SELECT event_type, severity, created_at FROM audit_events ORDER BY created_at DESC LIMIT 10;
```

## Code Style Guidelines

1. **Type hints everywhere**: All function parameters and return types should be typed
2. **Meaningful names**: `get_agent_by_id` not `get_a`, `policy_decision` not `pd`
3. **Explicit over clever**: Prefer readable code over one-liners
4. **Comments explain WHY, not WHAT**: Don't comment `# increment counter` on `counter += 1`
5. **Consistent error handling**: Use custom exceptions, don't swallow errors
6. **No magic strings**: Use enums for fixed sets of values (roles, risk levels, statuses)
